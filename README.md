# Змейка (SFML, C++17)

Готовый проект «Змейки» с меню, настройками, паузой и game over,
написанный на SFML. Ниже — как собрать и запустить, и как код закрывает
критерии из задания.

## Сборка

Нужен установленный **SFML 2.5+** и **CMake 3.16+**.

### Linux (Debian/Ubuntu)
```bash
sudo apt install libsfml-dev cmake g++
cd snake
cmake -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build
./build/SnakeGame
```

### macOS (Homebrew)
```bash
brew install sfml cmake
cd snake
cmake -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build
./build/SnakeGame
```

### Windows (vcpkg)
```powershell
vcpkg install sfml:x64-windows
cd snake
cmake -B build -DCMAKE_TOOLCHAIN_FILE=[путь_к_vcpkg]/scripts/buildsystems/vcpkg.cmake
cmake --build build --config Release
build\Release\SnakeGame.exe
```

CMake сам скопирует папку `assets/` рядом с исполняемым файлом после сборки
(см. `add_custom_command` в `CMakeLists.txt`), поэтому запускать бинарник
можно прямо из папки `build`.

## Управление

- Стрелки / WASD — движение
- Esc или P — пауза
- Мышь — клики по кнопкам меню/попапов

## Структура проекта

```
snake/
├── CMakeLists.txt
├── assets/
│   ├── images/   head.png, body.png, tail.png, apple.png
│   ├── fonts/    main_font.ttf
│   └── sounds/   eat.wav, game_over.wav
└── src/
    ├── main.cpp            — точка входа
    ├── Types.h             — общие enum'ы (Direction, Difficulty, GameState, SegmentKind)
    ├── Settings.h/.cpp     — синглтон настроек (сложность, звук)
    ├── ResourceManager.h/.cpp — загрузка текстур/шрифта/звуков через assert()
    ├── Snake.h/.cpp        — логика змейки: движение, рост, столкновения, отрисовка
    ├── Apple.h/.cpp        — яблоко и его спавн в свободной клетке
    ├── Button.h/.cpp       — переиспользуемая UI-кнопка для всех меню
    └── Game.h/.cpp         — стейт-машина игры (меню/игра/пауза/настройки/game over)
```

## Как это соответствует критериям задания

- **Перемещение** — `Snake::step()`: голова сдвигается по направлению,
  каждый сегмент занимает позицию предыдущего (алгоритм "следования",
  как описано в задании).
- **Увеличение длины** — `Snake::grow()` ставит флаг, при следующем
  `step()` в конец списка добавляется новый сегмент на месте бывшего хвоста.
- **Появление яблок и их сбор** — `Apple::respawn()` выбирает случайную
  свободную клетку; в `Game::update()` при совпадении головы и яблока
  начисляется очко и вызывается `grow()`.
- **Смерть змейки** — проверка столкновения со стеной и с собой в
  `Game::update()`, переход в состояние `GameOver`.
- **Логика интерфейса**:
  - «Начать игру» и попапы (game over, пауза) — `Game::state_` +
    соответствующие `renderX()`/`rebuildXButtons()`.
  - Смена сложности — кнопка в настройках циклически переключает
    `Difficulty` в `Settings`, от неё зависит `stepIntervalSeconds()`.
  - Настройки, вкл/выкл звука — `Settings::toggleSound()`,
    проверяется перед `sound.play()`.
  - Выход — кнопка вызывает `window_.close()`.
- **Разные текстуры для головы/тела/хвоста** — `SegmentKind` +
  `ResourceManager::segmentTexture()`, поворот спрайта под направление
  движения в `Snake::draw()` (плавные повороты).
- **Один code-style** — везде camelCase для переменных/функций,
  PascalCase для классов, `_` суффикс для приватных полей.
- **Нет дублирования** — вся логика кнопок вынесена в класс `Button`,
  вместо копипасты прямоугольник+текст+клик в каждом экране.
- **Файлы/структуры/функции** — один класс = пара .h/.cpp, каждый
  отвечает за одну зону ответственности (Snake, Apple, Settings,
  ResourceManager, Button, Game).
- **Динамическая память без утечек** — используется `std::vector`
  (сегменты змейки), сырых `new`/`delete` в проекте нет.
- **Статические массивы безопасны** — статических C-массивов в проекте
  нет вовсе (везде `std::vector`/SFML-контейнеры), поэтому выход за
  границы исключён по конструкции.
- **Нет закомментированного кода / неиспользуемых переменных** — код
  проверен на этот счёт; единственное исключение — `(void)x;` в
  `ResourceManager::loadAll()`, это осознанное подавление предупреждения
  о неиспользуемой переменной в релизной сборке (где `assert` — no-op),
  а не мёртвый код.
- **Без `goto`** — не используется нигде.
- **`assert()` при загрузке контента** — `ResourceManager::loadAll()`
  оборачивает каждую загрузку текстуры/шрифта/звука в `assert(...)`.

## Замена "пакмана" на змейку

В задании упоминается замена модельки "пакмана" из предыдущего задания на
змейку — в этом проекте она изначально сделана как змейка, отдельной
замены не требуется.
